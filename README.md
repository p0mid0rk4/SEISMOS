# СЕЙСМОС (SEISMOS)

**Сейсмическая система контроля периметра на геофонах GS-20DX.**

СЕЙСМОС — законченное решение для охраны периметра объектов любой сложности и
протяжённости. Система построена на сейсмических датчиках GS-20DX с
последовательным опросом цепочки геофонов, оцифровкой сигнала и передачей
данных по Ethernet с питанием PoE. Обнаружение, классификация и тревожная
логика работают в едином контуре, а рабочее место оператора доступно через
веб-консоль.

> Идейный аналог — система «Тополь» (многорубежная периметральная охрана).
> СЕЙСМОС реализует ту же логику «предупреждение → тревога → проникновение»
> на сейсмическом принципе с необслуживаемым полевым сегментом.

## Возможности

- **Последовательный опрос цепочки геофонов.** Датчики одной цепочки
  опрашиваются один за другим; мультиплексор АЦП переключает каналы, а
  результаты сводятся в единый поток отсчётов.
- **Обнаружение по STA/LTA + адаптивный порог (CFAR).** Устойчивое
  срабатывание на нестационарном фоне (ветер, дождь, снег) при сохранении
  постоянной вероятности ложной тревоги.
- **Классификация воздействий.** Шаги, группа людей, техника, подкоп,
  перелаз, удар по ограждению, вскрытие датчика, метео-шум. Экспертный
  (правиловый) классификатор с прозрачной оценкой уверенности.
- **Три уровня значимости.** «Предупреждение» (подход к ограждению),
  «Тревога» (сработка на ограждении), «Проникновение» (событие внутри
  охраняемой зоны) — как в классических многорубежных системах.
- **Зоны охраны и режим постановки/снятия.** Общая постановка на охрану и
  независимое управление отдельными зонами.
- **Журнал событий и тревог** в SQLite с аудитом действий оператора.
- **REST API и WebSocket-поток** событий в реальном времени.
- **Веб-консоль оператора** со схемой периметра, журналом, активными
  тревогами и графиком сигнала.
- **Стенд и самопроверка** без физического оборудования: генератор
  синтетических сигнатур и команда `selftest`.

## Архитектура в двух словах

```
   Полевой сегмент            Узел сбора                 Сервер (КПП / ЦП)
 ┌──────────────────┐   ┌────────────────────┐   ┌───────────────────────────┐
 │ GS-20DX  GS-20DX │   │ АЦП (24 бит)       │   │  СЕЙСМОС                  │
 │   │        │     │   │  │                 │   │  ┌─────────────────────┐  │
 │   ▼        ▼     │   │  ▼                 │   │  │ Движок обработки    │  │
 │ цепочка датчиков │──►│ мультиплексор      │──►│  │ STA/LTA → CFAR →    │  │
 │ (последовательный│   │ нормировка (мкм/с) │   │  │ классификация       │  │
 │  опрос)          │   │ Ethernet + PoE     │   │  └─────────┬───────────┘  │
 └──────────────────┘   └────────────────────┘   │            │              │
                                                 │   ┌────────▼─────────┐    │
   Питание по PoE ◄──────────────────────────────┼───┤ журнал + тревоги │    │
   (IEEE 802.3af/at)                             │   └────────┬─────────┘    │
                                                 │            │              │
                                                 │   REST API + WebSocket    │
                                                 │            │              │
                                                 │   ┌────────▼─────────┐    │
                                                 │   │ Веб-консоль      │    │
                                                 │   │ оператора        │    │
                                                 │   └──────────────────┘    │
                                                 └───────────────────────────┘
```

Ключевая идея: **на периметре нет электроники, требующей обслуживания и
питания** — геофоны пассивны, а вся обработка сосредоточена в узле сбора и
на сервере. Это снижает стоимость монтажа и эксплуатации протяжённых
участков.

Подробности: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Быстрый старт

### Установка

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
# либо как пакет (даёт команду seismos в PATH):
pip install -e .
```

Требуется Python 3.11+.

### Запуск сервера и консоли

```bash
seismos serve --host 0.0.0.0 --port 8000
# или без установки пакета:
python -m seismos.cli.main serve
```

Откройте в браузере:

- консоль оператора — <http://localhost:8000/>
- интерактивная документация API — <http://localhost:8000/docs>

### Проверка системы без оборудования

```bash
seismos selftest      # прогон эталонных воздействий через конвейер
seismos simulate --event vehicle --duration 3
seismos sensors       # вывод конфигурации датчиков и зон
```

## Командная строка

| Команда | Назначение |
|---|---|
| `seismos serve [--host H] [--port P]` | Запустить API и веб-консоль оператора |
| `seismos simulate --event <класс> [--duration S] [--sensor ID] [--seed N]` | Стенд: синтез воздействия и прогон детекции |
| `seismos selftest` | Самопроверка конвейера обработки на эталонных сигналах |
| `seismos sensors` | Печать конфигурации датчиков и зон |
| `seismos version` | Версия системы |

Доступные классы для `--event`: `footstep`, `group`, `vehicle`, `digging`,
`climb`, `impact`, `weather`.

## Конфигурация объекта

Описание объекта задаётся в `config/site.yaml`: датчики, цепочки и зоны
охраны. Пример:

```yaml
name: "Демонстрационный объект SEISMOS"
perimeter_length_m: 640

sensors:
  - {id: S01, name: "Периметр 0 м", zone_id: Z1, chain_index: 0, position_m: 0}
  - {id: S02, name: "Периметр 80 м", zone_id: Z1, chain_index: 1, position_m: 80}
  # ...

chains:
  - id: CH1
    transport: sim            # sim | udp | tcp | spidev | file
    sample_rate: 1000
    address: "127.0.0.1:4789"
    sensors: [S01, S02, S03]

zones:
  - id: Z1
    name: "Северный участок"
    kind: seismic
    priority: 2
    length_m: 200
```

Параметры приложения читаются из переменных окружения с префиксом
`SEISMOS_` (например, `SEISMOS_PORT=8000`) или из файла `.env`. Полный
перечень — в [docs/INSTALL.md](docs/INSTALL.md).

## Обработка сигналов

Конвейер одного канала:

1. **Полосовая фильтрация** 5–120 Гц (каскад биквадратных БИХ-фильтров) —
   область, где лежат полезные сейсмические сигналы при собственной частоте
   геофона 4.5 Гц.
2. **СКЗ по кадрам** — оценка энергии на коротком окне.
3. **STA/LTA** — отношение «короткое окно / длинное окно»; превышение
   порога означает начало воздействия.
4. **CFAR** — адаптивный порог, удерживающий постоянную вероятность ложной
   тревоги при изменении уровня фона.
5. **Удержание и замыкание события** — короткие импульсы одного воздействия
   склеиваются в единое событие (устраняет дробление журнала).
6. **Извлечение признаков** по «энергетическому ядру» сигнала (доминирующая
   частота, длительность активной части, амплитуда) и **классификация**.

Результат классификации отображается на уровень тревоги:

| Класс | Уровень |
|---|---|
| метео, шум | 0 — информация |
| шаги | 1 — предупреждение |
| группа, удар | 2 — тревога |
| техника, подкоп, перелаз, вскрытие | 3 — проникновение |

Подробности и обоснование порогов: [docs/DETECTION.md](docs/DETECTION.md).

## API

Базовый префикс — `/api/v1`. Основные группы:

- **system** — `/health`, `/status`, `/metrics`, `/simulate`
- **perimeter** — `/sensors`, `/sensors/{id}`, `/zones`, `/zones/{id}`
- **control** — `POST /arm`, `POST /disarm`, `POST /zones/{id}/arm`
- **events** — `GET /events`, `GET /events/recent`
- **alarms** — `GET /alarms`, `GET /alarms/active`, `POST /alarms/{id}/ack`,
  `POST /alarms/{id}/reset`
- **WebSocket** — `/ws` (поток событий, тревог, изменения состояния)

Полный справочник с примерами: [docs/API.md](docs/API.md).

## Консоль оператора

Веб-интерфейс (`console/`) показывает:

- состояние системы (на охране / снято / тревога) и часы;
- метрики: датчики на связи, зоны на охране, активные тревоги, события;
- схему периметра с подсветкой сегментов по уровню тревоги;
- список активных тревог с квитированием;
- журнал событий с фильтром по уровню;
- карточки зон с переключателями;
- график сигнала в реальном времени.

Консоль подключается к серверу по WebSocket и получает события без
перезагрузки страницы.

## Аппаратная часть

- **Датчик** — геофон GS-20DX (собственная частота 4.5 Гц, чувствительность
  28.8 В/(м/с), рабочий диапазон −40…+80 °C). Установка в грунт, заглубление
  на 0.3–0.5 м, контроль наклона не более 3°.
- **Узел сбора** — АЦП 24 бита (ADS1256) с последовательным опросом каналов,
  нормировка сигнала в мкм/с, упаковка в UDP-пакеты, питание PoE
  (IEEE 802.3af/at).
- **Сеть** — Ethernet 100BASE-TX по витой паре; допускается объединение
  питания и данных в одном кабеле.

Схема установки и рекомендации по монтажу: [docs/HARDWARE.md](docs/HARDWARE.md).
