# Алгоритмы обнаружения и классификации

Документ описывает конвейер обработки сигнала, пороги и логику принятия
решения о тревоге.

## 1. Конвейер одного канала

```
отсчёты (мкм/с)
   │
   ├─► 1. Полосовая фильтрация 5–120 Гц
   │
   ├─► 2. СКЗ по кадрам (frame_len = 64 отсчёта)
   │
   ├─► 3. STA/LTA: отношение короткого и длинного окон
   │
   ├─► 4. CFAR: адаптивный порог по опорным ячейкам
   │
   ├─► 5. Удержание события (склейка импульсов)
   │
   └─► 6. Признаки по энергетическому ядру → классификация
```

## 2. Полосовая фильтрация

Диапазон 5–120 Гц выбран под собственную частоту геофона 4.5 Гц: ниже
5 Гц отклик датчика подавляет сигнал, выше 120 Гц лежат шумы электроники и
высокочастотные помехи. Фильтр — каскад биквадных секций (БИХ второго
порядка), состояние секций сохраняется между блоками, поэтому сигнал не
«рвётся» на границах.

## 3. STA/LTA

Классический детектор отношения энергий:

- **STA** — короткое окно (по умолчанию `sta_len = 64` отсчёта, ≈ 64 мс);
- **LTA** — длинное окно (`lta_len = 1024` отсчёта, ≈ 1.02 с).

Реализация рекурсивная, что даёт низкую вычислительную стоимость. Оба окна
задаются в отсчётах и переводятся в кадры обработки (`frame_len = 64`).

Порог срабатывания `trigger_ratio = 3.5`, порог отпускания
`release_ratio = 1.6`. Гистерезис между порогами предотвращает «дребезг»
на границе срабатывания.

## 4. CFAR (адаптивный порог)

STA/LTA реагирует на относительный рост энергии, но не различает
абсолютный уровень фона. При усилении ветра, дождя или снега это даёт
ложные срабатывания. Поэтому срабатывание подтверждается детектором CFAR
(Cell-Averaging): порог вычисляется как `alpha × средний_фон` по опорным
ячейкам вокруг проверяемой, что удерживает постоянную вероятность ложной
тревоги при нестационарном шуме.

Параметры: `cfar_alpha = 4.0`, `cfar_ref = 16`, `cfar_guard = 4`.

Событие начинается, когда **одновременно** выполнены оба условия:
`ratio ≥ trigger_ratio` **и** `CFAR подтверждает превышение`.

## 5. Удержание и замыкание события

Воздействие на периметр редко бывает непрерывным: шаги дают серию
разнесённых импульсов, рокот техники — пульсации. Без удержания журнал
дробился бы на десятки микро-событий. Поэтому после падения сигнала
событие остаётся открытым `hold_s = 0.6` с, склеивая импульсы одного
воздействия. Событие закрывается, когда удержание истекло и длительность
превысила `min_duration_s = 0.08` с (либо достигнут `max_duration_s = 30` с).

## 6. Признаки и классификация

Признаки считаются по **энергетическому ядру** — участку буфера, где
амплитуда выше 25 % от пика. Это важно: хвост удержания содержит фоновый
шум и искажал бы спектр коротких импульсов (например, удара по ограждению).

Используемые признаки:

- **доминирующая частота** — максимум спектра (окно Ханна);
- **длительность активной части** — длина энергетического ядра;
- **пиковая амплитуда** — максимум модуля сигнала.

### Экспертный классификатор

Для каждого класса задан эталонный профиль (среднее и «ширина» по каждому
признаку). Оценка соответствия — произведение гауссовых функций подобия:

```
similarity = G(f, f0, σf) · G(dur, dur0, σdur) · G(amp, amp0, σamp)
score      = similarity^(1/3) · weight
```

Класс с максимальной оценкой побеждает; если оценка ниже
`min_confidence = 0.30`, событие помечается как `unknown`.

**Почему экспертная модель, а не обучение.** На объекте оператор должен
понимать, почему система отнесла событие к тому или иному классу, а
поведение классификатора — быть предсказуемым и объяснимым. Правиловый
классификатор даёт прозрачное решение и не требует размеченных данных с
конкретного объекта. При необходимости эталонные профили легко
перенастраиваются под местные условия.

### Профили классов (ориентировочно)

| Класс | Доминирующая частота, Гц | Длительность активной части, с | Пик, мкм/с |
|---|---|---|---|
| Шаги (`footstep`) | ≈ 25 | ≈ 2.5 | ≈ 6 |
| Группа (`group`) | ≈ 23 | ≈ 4.5 | ≈ 13 |
| Техника (`vehicle`) | ≈ 11 | ≈ 5 | ≈ 34 |
| Подкоп (`digging`) | ≈ 47 | ≈ 3 | ≈ 24 |
| Перелаз (`climb`) | ≈ 62 | ≈ 0.9 | ≈ 11 |
| Удар (`impact`) | ≈ 90 | ≈ 0.15 | ≈ 55 |
| Вскрытие (`tamper`) | ≈ 70 | ≈ 0.45 | ≈ 6.5 |
| Метео (`weather`) | ≈ 33 | ≈ 0.3 | ≈ 3 |

## 7. Уровни тревоги

Соответствие класса и уровня (`CLASS_LEVEL`):

| Уровень | Название | Классы |
|---|---|---|
| 0 | Информация (шум) | `weather`, `none` |
| 1 | Предупреждение | `footstep`, `unknown` |
| 2 | Тревога | `group`, `impact` |
| 3 | Проникновение | `vehicle`, `digging`, `climb`, `tamper` |

Тревога (`Alarm`) формируется движком при уровне ≥ 2 **и** если зона
поставлена на охрану **и** система в состоянии `ARMED` или `ALARM`.

## 8. Настройка порогов

Параметры задаются в `DetectionParams` (см. `core/config.py`) и доступны
через переменные окружения. Основные ручки:

- `trigger_ratio` — чувствительность; ниже → больше срабатываний;
- `cfar_alpha` — строгость подтверждения; выше → меньше ложных тревог;
- `min_duration_s` — отсев слишком коротких импульсов;
- `band_low_hz` / `band_high_hz` — полоса фильтра;
- `hold_s` — длительность склейки импульсов.

При настройке на реальном объекте рекомендуется сначала записать фон в
разных погодных условиях, затем подобрать `cfar_alpha` и `trigger_ratio`
так, чтобы фон не давал срабатываний, а эталонные воздействия (имитация
шагов, проезд техники) — устойчиво детектировались.

## 9. Самопроверка

Команда `seismos selftest` прогоняет эталонные воздействия через чистый
конвейер (для каждого случая — свой детектор, без переноса состояния) и
проверяет, что класс распознан, а тревога сформирована там, где ожидается.
Это быстрая проверка работоспособности обработки без оборудования.
