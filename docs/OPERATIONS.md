# Эксплуатация СЕЙСМОС

Документ описывает регламент дежурства, действия при тревоге, обслуживание и
диагностику.

## 1. Режимы работы системы

| Режим | Значение | Поведение |
|---|---|---|
| `disarmed` | Снято с охраны | События фиксируются, тревоги не формируются |
| `arming` | Постановка | Промежуточное состояние |
| `armed` | На охране | События уровня ≥ 2 формируют тревоги |
| `alarm` | Тревога | Активна хотя бы одна тревога |

Постановка и снятие — командами `POST /api/v1/arm` и `POST /api/v1/disarm`
либо кнопками в консоли. Зоны можно ставить/снимать независимо.

## 2. Регламент дежурства

1. **Начало смены** — проверить:
   - состояние системы (`armed`), все датчики на связи;
   - отсутствие не квитированных тревог от прошлой смены;
   - целостность каналов связи (нет датчиков «не на связи»).
2. **В течение смены** — реагировать на тревоги по алгоритму (раздел 3),
   контролировать поток событий.
3. **Конец смены** — передать смену с указанием активных тревог и
   незакрытых вопросов.

## 3. Действия при тревоге

1. **Зафиксировать** событие: зона, датчик, класс воздействия, уверенность.
2. **Проверить** участок визуально или по видео (при наличии).
3. **Квитировать** тревогу с комментарием:
   - «осмотрено, нарушителей нет» — ложное срабатывание;
   - «нарушение подтверждено» — передать группе реагирования.
4. **При подтверждённом нарушении** — действовать по инструкции объекта.
5. **Ложное срабатывание** — отметить причину (ветер, животные, техника вне
   периметра) и, при повторяемости, передать на подстройку порогов.

## 4. Классы событий и реакция

| Класс | Уровень | Реакция дежурного |
|---|---|---|
| Шаги | Предупреждение | Наблюдение, оценка направления |
| Группа | Тревога | Проверка участка, готовность ГБР |
| Удар по ограждению | Тревога | Проверка участка |
| Техника | Проникновение | Немедленная проверка, вызов ГБР |
| Подкоп | Проникновение | Немедленная проверка, вызов ГБР |
| Перелаз | Проникновение | Немедленная проверка, вызов ГБР |
| Вскрытие датчика | Проникновение | Немедленная проверка, вызов ГБР |
| Метео | Информация | Игнорировать (шум среды) |

## 5. Обслуживание

### Ежедневно

- Контроль состояния датчиков (все на связи).
- Просмотр журнала на предмет серии ложных срабатываний.

### Еженедельно

- Тестовое воздействие на разных участках (`seismos simulate` или кнопка в
  консоли) для проверки чувствительности.
- Проверка свободного места под базу данных и записи.

### Ежемесячно

- Проверка наклона и крепления геофонов.
- Осмотр боксов узлов сбора, герметичности, состояния PoE-линий.
- Резервное копирование базы `data/seismos.db`.

### Ежегодно

- Полная проверка кабельных трасс и соединителей.
- Перекалибровка порогов по фактическому фону объекта.

## 6. Резервное копирование

```bash
# Остановить сервис либо скопировать на «живой» БД (SQLite позволяет)
cp data/seismos.db backups/seismos-$(date +%F).db
```

Рекомендуется ежедневное копирование с хранением не менее 30 дней.

## 7. Диагностика

### Проблема: нет событий при воздействии

- Проверить режим системы (должен быть `armed`).
- Проверить, что датчик на связи (`GET /api/v1/sensors`).
- Проверить чувствительность: `seismos selftest`.
- Проверить полосу фильтра и порог `trigger_ratio`.

### Проблема: много ложных срабатываний

- Проверить погоду (сильный ветер, дождь, град).
- Поднять `cfar_alpha` (например, с 4.0 до 6.0).
- Поднять `trigger_ratio` (например, с 3.5 до 4.5).
- Проверить крепление геофона (плохой контакт даёт высокий фон).

### Проблема: датчик «не на связи»

- Проверить линию связи и питание PoE узла.
- Проверить бокс узла на попадание влаги.
- Проверить коммутатор на КПП.

### Проблема: события приходят с задержкой

- Проверить загрузку сервера (CPU) и сети.
- Проверить потери UDP-пакетов по счётчику `seq`.
- Уменьшить размер блока чтения или увеличить частоту опроса.

## 8. Метрики для мониторинга

- `sensors_online / sensors_total` — доля датчиков на связи;
- `active_alarms` — число активных тревог;
- `events_total` — суммарное число событий;
- число подписчиков шины (`subscribers`) — активные консоли.

## 9. Обновление системы

```bash
# 1. Резервная копия
cp data/seismos.db backups/seismos-preupdate.db
# 2. Обновление кода
git pull
pip install -r requirements.txt
# 3. Перезапуск сервиса
sudo systemctl restart seismos
# 4. Проверка
curl http://localhost:8000/health
seismos selftest
```
