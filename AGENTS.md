# AGENTS.md — память репозитория СЕЙСМОС

Памятка для будущих сессий агента. Описывает проект, команды и договорённости.

## Что это

СЕЙСМОС — сейсмическая система контроля периметра на геофонах GS-20DX
(идейный аналог многорубежной системы «Тополь»). Весь код и документация —
на русском языке: docstrings, комментарии, тексты интерфейса и документы.

## Команды

```bash
pip install -e ".[dev]"     # установка для разработки
pytest                       # 47 тестов, все должны проходить
seismos serve                # API + веб-консоль оператора
seismos selftest             # самопроверка конвейера обработки
seismos simulate --event vehicle --duration 3
python -m ruff check seismos tests   # линтер
bash scripts/demo.sh         # сквозная демонстрация без оборудования
```

## Структура

- `seismos/hardware` — геофон, АЦП, узел сбора, цепочка, генератор сигналов;
- `seismos/detection` — ЦОС, STA/LTA + CFAR, классификатор;
- `seismos/core` — модели, конфигурация, реестр, движок, хранилище, шина;
- `seismos/api`, `seismos/cli` — прикладной слой;
- `console/` — веб-консоль оператора (чистый HTML/CSS/JS, без сборки);
- `config/site.yaml` — конфигурация объекта;
- `docs/` — документация; `deploy/` — развёртывание.

## Договорённости

- Python 3.11+, зависимости перечислены в `pyproject.toml` и
  `requirements.txt` (держать их согласованными).
- Все изменяющие эндпоинты API защищены опциональным токеном
  (`SEISMOS_AUTH_TOKEN`); читающие — открыты.
- Детектор держит состояние (STA/LTA, CFAR) на каждый датчик. При стендовом
  прогоне каждому воздействию нужен «чистый» детектор и период базового шума
  (LTA-разогрев) — иначе срабатывание невозможно.
- Признаки классификации считаются по энергетическому ядру сигнала, а не по
  всему буферу (хвост удержания искажает спектр коротких импульсов).
- Классификатор — экспертный (правиловый), прозрачный для оператора. Профили
  классов заданы в `seismos/detection/classifier.py`.
- `sta_len` / `lta_len` задаются в отсчётах и переводятся в кадры обработки
  внутри `SeismicDetector`.
- Обоснование алгоритмов и порогов — в `docs/DETECTION.md`; при изменении
  порогов обновлять документ.

## Тестирование

- Тесты лежат в `tests/`, используют фикстуры из `tests/conftest.py`.
- `pytest-asyncio` в режиме `auto` (см. `pyproject.toml`).
- Тесты не должны требовать физического оборудования: стендовые сигналы —
  через `SeismicSignalGenerator`.
- Известное предупреждение: `StarletteDeprecationWarning` про `httpx` в
  `TestClient` — не является ошибкой.

## Git и публикация

- Рабочая ветка по умолчанию — `master`. Для изменений создавать ветку
  `feature/...`.
- Целевой удалённый репозиторий — `github.com/p0mid0rk4/SEISMOS`
  (ветка по умолчанию `main`). В нём уже лежит папка «Пример КД» с образцами
  конструкторской документации — не удалять.
- Для записи в репозиторий GitHub App OpenHands должен быть установлен и
  иметь доступ к `p0mid0rk4/SEISMOS` (приложение выдаёт короткоживущий токен).
  Если `git push` возвращает 403 «Permission ... denied», проверьте установку:
  `gh api /user/installations --jq .total_count` — должно быть больше 0.
- Публикация: ветка `feature/<имя>` → PR в `main`:
  ```bash
  git push -u origin feature/<имя-ветки>
  gh pr create --repo p0mid0rk4/SEISMOS --base main \
    --head feature/<имя-ветки> --title "..." --body-file .github/PR_BODY.md
  ```
- Первый PR (#1) с системой СЕЙСМОС 1.0.0 смержен в `main`.
